# S10F 有界审查

同一执行者在实现后独立阶段检查契约、真实事务与查询、客户端恢复；没有使用子Agent，不声称另一人独立评审。产品审查无待整改阻塞项；最终运行验证已通过，见TEST_RESULT。

- 当前列表严格由可信tenant/owner、ACTIVE/lifecycle_ready与active_job共同限定；名称来自任务的不可变修订，重索引不会混用失败新稿。筛选与游标同时绑定所有条件，限额和稳定排序由SQL执行。
- 受理核对依赖原CAS事务的RETRY事件，按(job,revision)现有索引读取；不按任务当前状态推断。原owner在撤下/删除后仅可核对无正文元数据，异owner/tenant为null；数据库失败503。
- 客户端冻结原任务/版本，最大10项串行；发送前持久化UNKNOWN。查询先行，202或匹配事件才确认；不自动换revision，刷新不自动POST，未知结果阻止下一项。已受理不可降级、批次ID阻止迟到回调改写新批次。
- sessionStorage按scope摘要隔离，只存标识/原版本/安全错误，无名称/正文/凭据；存储失败阻止发送。现有本地身份桥仅扩充两个GET，服务端仍校验权限，不等于生产IAM。
- 失败阶段与建议、历史记录、当前发布来源分开展示；修正文档的引导不误导用户重复上传原文件。1440任务、414部分结果/来源历史截图已实际查看：无横向页面溢出，操作可见，表格保留自己的横向滚动。
- 代码卫生HF-001指出retry-batch空catch：保留UNKNOWN的语义原已存在，现将异常分支显式持久化UNKNOWN并stop=true；恢复单元/三视口协议及新容器均已复核通过，无检查豁免。

边界：任务处理成功与重试受理是不同结果；批量没有全有全无事务，sessionStorage不是服务端批次数据库。Java仓库未配置formatter/独立静态分析，保留COMPLETE_WITH_LIMITATIONS；不为本片新增框架。真实dev无历史RETRY事件，正例由关闭worker的真实test库HTTP竞争及持久查询验证。
