# S14B 实施审查

按 operations-candidate-v1 核对本片范围。当前代码无未解决的阻断项；实际验证和交付门禁分别见 TEST_RESULT 与交付收据。

- 所有权：候选从反馈对应的原资料 owner 派生，所有 SQL 绑定 tenant/owner；GET 不授予写权限，POST 同时要求 knowledge:write。身份列为逐字比较；共享 reader、陌生人和跨租户无法编辑或读取候选。私有副本从首次 INSERT 就带目的及候选身份，与关联/作业同事务提交。
- 数据：V16 的六张表及字段均有注释；每反馈一个候选、每修订一个副本、tenant/owner/key 命令唯一。完整修订不可变，内容摘要绑定源字节、类型、大小、标题、原资料修订和文字要求。CAS 冲突不会留下命令回执或覆盖旧修订。源对象在事务外写入，未知/失败后保留，避免删除并发使用的内容寻址对象。
- 检索与兼容：默认普通列表、活跃内容查重、双索引候选过滤及 MySQL 最终复核均排除副本；显式 owner 范围可走同一检索/质量服务。旧无 purpose 的 STANDARD 索引继续工作，普通 K07 仍返回原 13 字段；只有副本追加目的/候选/修订。共享、通用更新/撤下/删除/重索引、对副本提交反馈均拒绝。
- 质量事实：复用 S8 的定义、实际中央任务终态、报告清单和人工评分。关联必须精确对应当前副本源/发布元组及定义修订；编辑、原资料变化、报告/评分改变使绑定失效，依赖失败为 UNAVAILABLE。只有 BUSINESS、既有人工资格与局部文字检查同时满足才显示审批前置。副本 READY 和机制夹具均不等于批准或原资料生效。
- 并发与失败：锁原资料再锁候选，使用 READ_COMMITTED/5 秒短事务；S3、中央任务和质量读取在事务外。原键重放优先，响应未知不换键。前端确认回执前验证规范请求摘要；遇到确定冲突仍先查原回执以覆盖同键并发，未确认时保留原键与当前草稿。页面内新草稿不会被旧回执收起。
- UI：反馈入口、完整正文/附件、历史、准备状态、只读副本、质量定义和报告关联复用现有 React/Ant Design 组件与真实 API；质量新定义只把当前副本作为范围，不复制反馈片段为全文。显式采用最新基线时保留草稿；sessionStorage 不保存正文、附件、标题或评分文本。截图检查发现副本沿用普通“已发布”文案，已改为“校验副本已就绪”并说明原资料生效仍需批准。
- Runtime：默认关闭，显式 --operations 仅开启候选入口，不隐式打开模型 worker 或改变预算。purpose 映射按明确 test/dev 目标追加；本轮仅 test，未部署。真实浏览器桥仅支持夹具随机主体、固定本机服务，签名私钥不进入浏览器；转发真实 multipart 原字节，不替换业务响应。

Java 无独立格式器是既有工具限制；沿周边源码风格人工复核。卫生工具的数字、枚举和事务建议已按协议常量/测试边界/上述短事务分类；未引入新依赖或中间件。三个既有 Runtime 文件的 5 条 Ruff 提示与 HEAD 完全相同，本片新 Python 文件 Ruff 通过，未借此修改无关旧代码。

读模型的质量资格是当次观察结果，跨服务无分布式原子快照；S14C 的真实审批发布必须再次验证内容、原资料修订及报告/评分身份，不能把本片展示结果当持久授权。S14C/D 尚未实现，不在本片宣称完整运营闭环。
