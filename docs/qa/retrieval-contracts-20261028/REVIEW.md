# S11A 设计反例审查

同一执行者在取证/初稿后进行第二阶段审查，未使用子Agent。结论：设计范围无未处理阻塞项；产品行为和真实模型仍待Owner片执行。

| 反例 | 约束与处理 |
| --- | --- |
| 过滤第2名后把原第3名当第2名，虽RRF公式不变仍改变结果 | sourceRank在原列表确定并保留空位；金标包含相同融合分数与chunkId同分顺序 |
| 同一段文字在两份资料出现，node.hash去重错误吞掉来源 | 用完整稳定身份；同文异资料金标要求保留两项 |
| 将跨源同一合法块计为被剔除，错误触发扩展/503 | 明确剔除按原始chunk/batch唯一身份的授权结果，不按两路条目数量差 |
| Java先融合只给5项，Python再重排无法恢复第6项以后 | 候选原语不融合；RRF兼容路径target=topK，重排路径target=50，融合后才选50项模型输入 |
| 旧Java可返回不足K的干净候选，新扩展规则改变旧语义 | K≤20且没有剔除时，合法唯一数<K意味着两路都未满20；新停止条件与旧路径等价，污染不足仍最终503 |
| 撤下发生在候选读取之后，或提供方返回伪造正文 | 外发前与最终输出前解析完整身份/textHash，失败整体拒绝；提供方只提供映射分数，不授予权限 |
| public Java调用Python后，Python回调占用同一个满信号量 | Java公共门面不持有候选原语资源；原语不反调Python；单一deadline/有限并发，由B/C真实故障验证 |
| 30秒总预算被每个索引轮次/模型/解析重新开始 | 每步夹紧到同一单调剩余期限，6次索引/一次Embedding/一次模型上限；不把各阶段上限相加当总预算 |
| 模型计费未知后回退并重试，或把RRF降级算真实精排 | 保守预留保持、无自动重试；默认FAIL；另一个冻结策略才允许RRF_ONLY且显式标记；授权故障永不降级 |
| 全局策略默认改动导致旧PG任务恢复成新算法 | legacy缺字段固定旧策略；新策略进入不可变配置/请求指纹，S11E验证历史恢复和公共边界 |

初稿中的不存在SERVICE_UNAVAILABLE枚举已按实际KnowledgeError纠正为DATABASE_UNAVAILABLE；LlamaIndex默认异步后处理会桥接to_thread，新增明确原生异步覆盖要求。另明确索引现有枚举为KEYWORD，wire的lexicalCandidates不意味着更名原枚举。没有新增数据库/服务/框架/价格假设。

U04依然是S11D真实调用条件，不能由设计审查自评为模型已开通或质量提高；U01/U03/U06保留。S11E公共响应和任务接入字段按本契约约束增量冻结，不提前改写已发布API。
