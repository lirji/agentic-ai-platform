# S13B/C 审查

本轮由同一执行者完成独立于实现步骤的契约/安全/事务/界面复核；没有子Agent，也不称第三方独立签收。结论以TEST_RESULT及validation.json的最终状态为准。

## 不变量与证据

- 所有者命令仍以可信tenant+owner定位。准入成员只获得明确逐份ACL的当前发布读权限；不转授、不编辑、没有团队或运营管理员。只读详情与消费摘要不返回owner草稿/任务/存储位置。原owner管理接口仍404拒绝接收者。
- 共享修订与生命周期修订分离，短事务同一document锁、CAS、当前ACL和不可变回执原子提交。并发同键只产生一次审计；回执重放先于当前状态检查，旧GRANT回放不复活已撤权ACL。唯一键冲突在事务结束后重读；外部成员请求不持锁。重复新键操作按契约留审计。
- 发布SQL保持租户、当前job、代次、内容摘要和READY约束，仅扩展到当前同组织成员的明确ACL。索引仅按tenant AND (owner OR共享documentId)预过滤，最终正文重读MySQL权威；即使索引仍保留旧payload，撤权后也不能取得正文。
- 不缓存成员ALLOW；成员停用/IdP故障时共享读取失败，所有者仍可撤权。本次Casdoor只读适配、JSON限制、独立HTTP容量和期限沿原基础设施，没有新增IAM写或目录副本。搜索的IAM核验耗时计入索引剩余预算。
- 评测读定义/标注/报告、人工评审和基线选择均经当前绑定检查；数据库行锁保护共享撤权与定义写入的观察点。任务历史/事件和恢复沿原证据检查，真实跨服务验收覆盖QA、研究、评测、PG接管、生成中撤权以及召回后外发精排前撤权。
- UI遵守服务端允许动作；未知写入保留原intent，GET原键恢复并核对指纹，不能悄悄换键重复授权。共享详情/列表错误不展示旧成功缓存。共享读者可走引用详情与检索范围选择器；会话/研究任务自身仍私有。

## 已整改

1. 同级React key与版本历史相同导致共享面板重复：唯一前缀修复，真实浏览器复验。
2. 旧选择器只读owner摘要导致共享资料无法选择：增加统一readable-documents投影，问答/检索/评测共用；保留原管理API不扩权。
3. 引用详情原只走管理页：404后只尝试共享只读投影，页面没有owner动作。全局“仅本人可见”旧文案与事实不符，已改成默认私有/指定共享，管理权限仍仅本人。
4. 共享输入有界读取与严格JSON，拒绝重复/额外键、浮点修订和伪造主体；资料类型复用既有DocumentContentType。
5. 回归故障注入夹具漏加载新增SharingMapper SQL片段：修正测试装配，仍验证真实不可达MySQL转DATABASE_UNAVAILABLE，没有放宽产品行为。
6. 测试前置及断言修正：协议模型没有Mockito依赖；隔离评测显式开新版检索；撤权历史Task按既有404契约验证。旧浏览器fixture明确共享关闭。

## 边界与非阻断项

权限核验与模型外发之间没有跨系统原子事务；已经送达的文本无法追回。当前成员目录和MySQL重验缩小窗口，仍按契约逐边界拒绝。已打开页面按现有刷新与共享5秒轮询更新，不宣称服务器推送撤文。

机械代码卫生工具对命名常量数值、TransactionTemplate给出建议，已按上述事务锁序/回滚/远程调用/幂等逐项审阅。Java没有独立格式器，沿周边风格；现有Flyway对MySQL8.4的提示、Vite块大小/原扩展名提示及Deep Agents无内部saver提示保留。无新增依赖；本片不是容量压测、真实模型质量证明或生产发布。
