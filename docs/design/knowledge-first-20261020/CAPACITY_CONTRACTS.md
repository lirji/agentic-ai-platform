# C-CAPACITY：显式worker分工、租户份额与有界恢复

运行清单协议`worker-group-v1`，预检结果协议`worker-group-check-v1`。当前冻结S16A与S16B；S16C混合容量和S16D告警仍须后续各自验收。U06未定，只报告隔离实验，不宣称生产SLO。

## Worker与领取

- 每进程保持一个在途任务，不新增线程池或隐藏模型并发；中央MySQL任务/epoch仍是唯一租约权威。PG只恢复中央确认过的快照。
- WorkerConfig增加可选 `graph_versions`（非空、不重复、已知版本枚举）；省略时保持原已启用版本轮询。显式选择必须是本配置的真实能力子集：v2/v3/v4检索图需retrieval_enabled，QA v3还需contextual_qa_enabled，评测图需evaluation_private_key。禁止领取后才发现未装配所需能力。
- 内部claim接口不变；配置是调度分工，不是额外身份授权。客户端收到的lease必须匹配本次graph/runtime、固定tenant和workerId，否则协议拒绝，不执行模型。关闭新任务入口不妨碍旧图排空。
- 旧worker只领取自身支持版本，新worker可显式分工旧/新图；不重写历史输入、PG快照或旧graph ID。已有默认配置兼容。

## 首轮运行预算

首轮隔离验收两个独立worker，各一个在途，共2任务。每进程PG最大4（总8）、Tasks HTTP4（总8）、Usage HTTP4（总8）、Knowledge HTTP2（总4）、Evaluation HTTP2（总4）。Chat与ToolChat各1连接、每任务只用其中一条；Embedding与Rerank保持原适配器上限。按配置逐实例求和，连接上限不是吞吐承诺。Java服务/模型代理/在线HTTP进程另外计，不把单进程限制误称全平台限制。

多实例使用CENTRAL共享预算及不同worker_id的私密配置，原LEGACY_LOCAL长期单worker不自动升级。不能复制本地累计账本为每个进程新增余额。调用前原reserve/dispatch及任务/研究次数预算沿S15B/S12D，未知结果继续占额，接管不清零。组配置预检验证私密路径/唯一身份/同目标服务及checkpoint DSN/总资源，不替代每进程原启动预检，不授予新费用或部署权限。

S16A不声称提供跨任意实例数量的全局并发配额；S16B负责跨实例资源准入和公平。当前组由显式运行清单限定，新增实例须重新核算。

## S16B冻结：租户预留份额与后台隔离（capacity-policy-v1）

本片选择显式静态份额、暂不借用空闲份额。每种资源的全部租户份额之和不得超过该服务数据库所辖全局上限；满额租户不能领取其他租户的预留容量，因此无需依赖请求竞速实现公平。代价是空闲份额不自动贡献吞吐；U06尚未定义时先保证隔离，后续改变调度策略需独立验证。租户内任务按原稳定FIFO；此契约不承诺同租户不同owner的公平权重。

- Tasks拥有交互任务与后台任务两份独立额度。RESEARCH/KNOWLEDGE_EVALUATION为后台，其余沿已注册任务类型为交互。按tenant和lane计有效RUNNING租约；排队+执行总量另设有界上限。受理/恢复超额返回统一`TASK_CAPACITY_EXCEEDED`/429，幂等重放不再占队列；worker满额领取返回原空结果，持久任务不丢弃、租约不变。
- Knowledge拥有入库、在线搜索和候选回调三类份额。入库计有效PROCESSING租约，原持久RECEIVED保留；候选筛选先排除满额租户，避免其最早20条饿死其他租户。新受理/更新/重索引/失败重试/候选副本准备/候选批准统一限制尚未终结的入库队列。在线搜索与候选回调使用不同数据库许可，防止Java→Python→Java持同一许可自锁；旧搜索与新搜索归同一在线预算。瞬时超限沿`KNOWLEDGE_BUSY`快速拒绝，不新增内存等待队列。
- 配额只由固定部署配置提供，不接受客户端tenant、lane或limit覆盖。未知租户不获新额度。每服务最多32个配置租户，配额合计/字段范围启动校验。固定策略摘要持久到各自数据库；实例启动和领取核对同一策略。已登记策略不能被另一配置或关闭开关实例绕过；首次启用必须包含全部未终结任务的租户及所用lane，有效旧租约不得超过份额；已经受理的排队任务可高于新队列上限，保留并排空，期间拒绝追加。策略调整须先停全部写入者，后续受控升级单独审计，不自动覆盖。迁移只追加Tasks V8与Knowledge V19，应用账号只有DML；所有表/列写中文注释。
- 数据库短事务内串行化准入，网络调用始终在提交后。Tasks顺序为capacity→task；Knowledge沿capacity→document→job，仅释放资源的操作不再取得容量锁，避免唯一索引与配额锁反序；在线许可只锁自己的容量记录。配置不一致、数据库不可用均拒绝，不退回本地Semaphore。
- 任务/入库许可有效期使用原数据库租约及fencing，关停停止领取并取消等待，租约到期后可续办。在线许可有固定有界期限，原端到端deadline必须先于许可到期；释放匹配随机token，迟到释放不能释放继任者。许可上限是有效本地执行权，不声称外部提供方取消成功或未知调用免费；S15B未知费用占额不变。
- 原本地HTTP/DB连接池及独立入库/评测执行器继续保留保护层；启用时入库循环和解析进程槽位按入库份额求和，在线转发按搜索份额求和，本地查询许可和共用HTTP按对应全部份额求和，避免旧单槽或2/3额度反过来破坏数据库预留份额；未启用保持原值。候选批准在run→document之前取得capacity锁，候选副本与普通入库共用队列。跨实例总量由租户份额求和。业务授权仍显式传递不可变Caller，禁止经线程上下文传播认证凭据/事务连接；Micrometer与Python ContextVar需验证复用、异常和取消后的恢复。未引入自定义Java业务ThreadLocal时不为形式加入TTL容器；若实现需要该上下文则必须用TTL并验证捕获/恢复。
- 新模式默认未登记，不调整长期服务或原预算。混用旧二进制无法遵守新许可，因此新模式只能在全部相应写入者升级后启用。S17继续验证固定制品升级窗口。

Python HTTP检索新增显式`AI_RETRIEVAL_MAX_CONCURRENT`（1–8，默认1），入口和用例使用同一配置；它是本进程保护上限，不能代替Java跨实例份额。部署须匹配搜索份额，并使处理API及Embedding连接池覆盖入库+在线峰值，按实例汇总。提供方限流、Rerank账本/连接等仍可快速拒绝，公平机制不承诺外部资源吞吐或付费结果。具体首轮资源配置见CAPACITY_RUNTIME。

本片实验采用独立test数据库内的合成租户、两个服务实例/受控worker，所有配额是实验值。策略一旦登记会拒绝其他配置，因此使用新的本项目隔离test数据库，避免污染既有test任务与长期配置；保留全部数据及日志，不覆盖共享库，不生成真实模型费用。
