# C-CAPACITY / S16A：显式worker分工与有界恢复

运行清单协议`worker-group-v1`，预检结果协议`worker-group-check-v1`。当前只冻结S16A；S16B公平准入、S16C混合容量和S16D告警须后续各自验收。U06未定，只报告隔离实验，不宣称生产SLO。

## Worker与领取

- 每进程保持一个在途任务，不新增线程池或隐藏模型并发；中央MySQL任务/epoch仍是唯一租约权威。PG只恢复中央确认过的快照。
- WorkerConfig增加可选 `graph_versions`（非空、不重复、已知版本枚举）；省略时保持原已启用版本轮询。显式选择必须是本配置的真实能力子集：v2/v3/v4检索图需retrieval_enabled，QA v3还需contextual_qa_enabled，评测图需evaluation_private_key。禁止领取后才发现未装配所需能力。
- 内部claim接口不变；配置是调度分工，不是额外身份授权。客户端收到的lease必须匹配本次graph/runtime、固定tenant和workerId，否则协议拒绝，不执行模型。关闭新任务入口不妨碍旧图排空。
- 旧worker只领取自身支持版本，新worker可显式分工旧/新图；不重写历史输入、PG快照或旧graph ID。已有默认配置兼容。

## 首轮运行预算

首轮隔离验收两个独立worker，各一个在途，共2任务。每进程PG最大4（总8）、Tasks HTTP4（总8）、Usage HTTP4（总8）、Knowledge HTTP2（总4）、Evaluation HTTP2（总4）。Chat与ToolChat各1连接、每任务只用其中一条；Embedding与Rerank保持原适配器上限。按配置逐实例求和，连接上限不是吞吐承诺。Java服务/模型代理/在线HTTP进程另外计，不把单进程限制误称全平台限制。

多实例使用CENTRAL共享预算及不同worker_id的私密配置，原LEGACY_LOCAL长期单worker不自动升级。不能复制本地累计账本为每个进程新增余额。调用前原reserve/dispatch及任务/研究次数预算沿S15B/S12D，未知结果继续占额，接管不清零。组配置预检验证私密路径/唯一身份/同目标服务及checkpoint DSN/总资源，不替代每进程原启动预检，不授予新费用或部署权限。

S16A不声称提供跨任意实例数量的全局并发配额；S16B负责跨实例资源准入和公平。当前组由显式运行清单限定，新增实例须重新核算。

## 恢复验收

| ID | 必需结果 |
| --- | --- |
| MW01 | 默认配置兼容；版本选择未知/重复/能力不匹配拒绝；claim响应错误身份/版本不进入执行 |
| MW02 | 两独立Python进程真实竞争同一中央任务只授予一个有效epoch，未领取者不调用模型 |
| MW03 | 已确认研究计划后退出/接管，从确认阶段继续；真实PG与中央凭据一致，旧epoch心跳/完成/写入不变成有效新结果 |
| MW04 | 取消、迟到心跳、完成响应未知、进程退出与重启；任务状态不被旧执行者覆盖，模型/工具累计预留不清零 |
| MW05 | 旧图和新图明确分工/兼容；组内身份唯一，CENTRAL预算/连接总量预检及有界关停可验证 |

所有实验仅使用现有登记test数据库、受控模型端口与本任务合成数据；不增加真实费用、不调整长期服务、不清理历史数据。CLI与运行说明形成完整具体命令后才执行隔离验证。
