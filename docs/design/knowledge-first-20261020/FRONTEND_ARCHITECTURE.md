# React 知识工作台设计

依据：[首期约定](BRIEF.md)、[后端架构](../platform-selection-20261020/BACKEND_ARCHITECTURE.md)、[契约](CONTRACTS.md)。首期为 Greenfield；独立 React 仓库已完成 S4–S7 的资料、问答、研究及只读助手，后续在此基础上增量扩展，不迁入旧 Vue 工程。已有真实浏览器与 1440/1024/414px 截图证据，验收范围见相应任务记录。

## 1. 用户与首条路径

- 使用者：在可访问的知识范围内问答、研究、使用业务助手。
- 资料维护者：维护知识内容，查看入库进度、版本及失败原因，处理允许重试的任务。
- 运行管理员：管理接入与授权配置；不因管理界面角色自动取得全部文档内容。

角色是任务划分；真实权限来自后端身份与资源授权。首条代表路径为：进入知识文档列表 → 上传资料 → 查看入库状态 → 打开已发布文档 → 提问 → 核对引用。上传结束与入库发布分别展示。

## 2. 应用与技术约定

- 单个中文企业工作台 SPA，前端独立 Git 仓库；仓库为 `agentic-ai-platform-web`，独立原目录和任务分支；远程交付以进度为准。
- React、TypeScript strict、Vite、Ant Design；React Router 管路由，TanStack Query 管服务端状态，Axios 管 JSON 请求；SSE 使用契约支持的流式客户端。
- 表单使用 Ant Design Form，主题由 ConfigProvider/tokens 统一管理，业务样式使用 CSS Modules，pnpm 管依赖；Zustand 仅在跨页 UI 状态确有需要时加入。
- 具体依赖版本在前端首片通过兼容核对后锁定；不因选了框架就假定已有可运行工程。

## 3. 导航与界面覆盖

路由名是前端设计，不表示对应服务已实现。业务接口就绪后才开放可操作入口，导航不放无功能的占位按钮。

| 路由/入口 | 用户任务与主要内容 | 操作/容器 | 契约依赖与完成标志 |
| --- | --- | --- | --- |
| `/knowledge` 知识资料 | 查找文档，按范围、名称、处理状态筛选；展示文档 ID、名称、版本、状态、范围、更新时间等独立列 | 上传短表单用模态；行名称打开完整详情；失败任务可进入处理详情 | K01–K03；收到真实任务状态，发布成功后才可进入问答 |
| `/knowledge/documents/:documentId` 文档详情 | 原文定位、版本、发布状态、处理结果及失败原因 | 完整路由承载长内容和深链；重试只有服务端允许才显示；返回保留列表筛选 | K02–K04；文档、版本与授权一致 |
| `/chat/:conversationId?` 知识问答 | 知识范围、会话、问题、回答、来源证据 | 主阅读区加引用侧栏；提交/停止为上下文动作；引用可打开文档完整详情 | Q01–Q03；回答终态已确认，引用指向可访问的文档版本 |
| `/research` 与 `/research/:taskId` 研究分析 | 提交多资料研究任务，查看任务阶段、证据与报告 | 短输入与任务列表；长任务详情使用完整路由；取消需要说明已完成结果不会被撤销 | T01；由后续研究契约补充制品 schema，当前不伪造进度或报告 |
| `/assistants` 与 `/assistants/tasks/:taskId` 业务助手 | 选择已发布的助手能力，提交任务并检查工具结果 | 按具体任务提供表单与结果；写工具的批准界面等正式契约确定后加入 | T01 与后续工具契约；不能仅以模型文本宣称业务动作成功 |

菜单按资料维护、问答、研究、助手的实际任务区分；首页先进入知识问答或资料工作区，不制作重复导航的卡片门户。

## 4. 目录与依赖方向

```text
src/
  app/                 # 路由、应用启动、身份上下文和唯一主题
  pages/               # 路由编排，不承载接口或领域权威状态
  features/
    knowledge/         # 资料列表、上传、版本与入库状态
    chat/              # 会话、流式回答、引用
    research/          # 研究任务与报告
    assistants/        # 助手任务与受控工具交互
  shared/
    api/               # 按契约生成/封装的客户端与错误归一
    ui/                # 主组件体系上的共享原语
    lib/               # 时间、显示格式等无领域副作用工具
  test/                # 契约测试与测试工具
```

目录按首次需要创建，不预建空模块。业务 feature 不导入其他 feature 的私有组件；共享引用展示由明确的公共组件/类型承接，不借共享目录泄漏后端实体。

## 5. 状态、权限与恢复

- 查询、分页、可分享的文档/任务标识进入 URL；密钥、令牌和文档内容不进入 URL。
- 服务端数据使用 Query 缓存，键包含当前用户/租户及查询范围；切换身份或范围时撤销旧请求、隔离缓存及草稿，拒绝旧响应覆盖新页面。
- 表单临时值与本地 UI 状态独立。演示业务数据由种子写库再经 API 获取，页面不写死业务列表。
- 所有主要页面/详情覆盖 loading、empty、error、forbidden、not-found 及适用冲突；服务故障不显示为空数据。
- `202` 表示受理，持续显示处理中；流式断开先查询任务/回答状态，再按服务端游标恢复，不能自动创建重复任务。
- 校验或网络错误保留有效输入；未知写入结果使用原幂等键查询/重试，不重新生成键。`409` 提示刷新当前版本后再操作。
- 引用默认展示原文摘录、文档名与位置；生成分析分开标识。未经授权的引用按统一不可用状态呈现，不能泄露文档名称。

## 6. 视觉方向与交互验收

已确认个人偏好为简洁、清楚的信息层级与操作；当前项目没有专属品牌或用户确认的样稿。以下主题是可调整的工程假设，不记作用户视觉验收：

- 浅色中性画布、白色作业面，单一靛蓝主动作色；状态同时有文字，不只靠颜色。主题统一映射到 Ant Design token，避免第二套 Button/Table/Form。
- 桌面侧栏约 208px，内容区 24px 留白；标题 24px、正文/表格 14px、辅助文案 12px，控件以 36px 舒适密度起步；数值需在真实内容截图中复核。
- 中文使用系统字体栈；第一条业务路径不需要营销插图或外部图片。长文档名可展开，ID 可复制；状态、版本、范围与时间独立分列，遵守个人列表偏好。
- 上传模态使用可见标签与说明，校验失败保留输入，提交时防重复；成功进入任务状态而不是提示已发布。模态焦点、Esc、关闭与输入保护沿主组件行为。
- 引用侧栏用于快速核对，文档/研究详情使用完整路由；侧栏不再嵌套模态承载长报告。返回列表保留有效筛选、分页和位置。
- 主要支持桌面；首次验收使用 1440/1024px 及 414px 窄屏布局检查。窄屏导航折叠、表格内部滚动、长详情单列；不因此新增独立移动产品。
- 代表路径需实际操作上传、状态查看、问答、引用打开和返回，并查看页面与模态截图；错误、空态、权限拒绝、长内容及键盘焦点纳入验收。S4 已有当前浏览器/截图证据，未冒充用户视觉签收。

### S8B 质量定义界面增量

沿用现有工作台壳层、Ant Design、TanStack Query 和错误目录，增加 `/quality`（本人的评测集、用途筛选和游标）与 `/quality/:datasetId`（当前定义、历史修订、编辑）。契约为 [E01](QUALITY_CONTRACTS.md)。编辑表单允许逐题选择当前已发布资料和原文片段；正确证据与参考答案分栏呈现，NO_ANSWER 显示拒答评分标准并禁止证据。空集可保存但不显示尚未实现的运行操作。保存冲突/失败保留草稿，未知结果保留提交键并可恢复查询；回到列表保留筛选，详情失效清空正文。页面覆盖 1440/1024/414 px，实际业务数据全部来自 API。


### S8C：评测运行与逐题结果

在定义详情增加运行当前修订与运行记录，固定读取已保存修订；未保存草稿不能直接执行。完整运行页为 `/quality/:datasetId/runs/:runId`，展示真实交接/中央状态、确认报告摘要、逐题选择、答案/标准/召回与耗时/费用，沿用原文侧栏。运行记录用独立 `runCursor` 保留定义页筛选；定义与运行均按身份隔离缓存。

创建命令复用原 sessionStorage 幂等注册表，仅保存请求摘要、修订和原键；未知结果先查回执，404 后可按原修订原键重发。取消/恢复确认使用 E02 CAS；未知控制结果刷新原运行，不能换任务重跑。运行中展示中央进度题号与阶段，不伪造完成比例；失败前缀和恢复后的上次报告明确标识。当前绑定/读取失败时隐藏报告正文，未开始、未确认、空召回、无答案题和执行失败分别呈现。界面沿用现有主题、Ant Design 与 TanStack Query，验收 1440/1024/414px 和键盘/焦点。


## S8D 评审与比较增量

依照[E03](EVALUATION_COMPARISON_CONTRACTS.md)，逐题结果下新增适用维度评分、理由与不可变历史侧栏；沿用原提交意图/错误/权限/原文侧栏与组件体系。运行头部以服务端资格解释设基线是否可用，禁止用前端均分判断合格。比较路由`/quality/:datasetId/runs/:runId/compare?baselineId=...`采用完整页面，先呈现门禁和原因，再分列执行/检索/人工/耗时/费用及逐题变化；窄屏上下排列，保留同一道题与对照身份。点击具体题可精确读取两侧manifest的实际回答与引用，不在列表加载100份正文。表单草稿不被轮询覆盖；未知评分/基线提交按原键核对，409保留编辑并显式采用最新修订。当前资料失效或403立即隐藏正文与评分。所有数据来自真实E03/E02，测试夹具只在验收工具。
