# C-RELEASE：固定制品与隔离验证（S17A）

沿既有Java/Python/Web/模型代理九容器拓扑，不新建业务服务或共享基础设施。复用dev-infra MySQL8.4/PG16/MinIO和本项目ES/Qdrant；禁止隐式连接参考旧业务服务。S8F的CI协议继续生效。

## 制品与边界

`release-artifacts-v1`绑定sourceFingerprint、前后端提交、每个Compose服务的image引用与Docker不可变imageId、构建配方来源。build成功后记录；up前重新核对全部imageId和源指纹，tag已变化、服务清单不同、缺少收据、快照被更改均拒绝启动。旧收据无不可变ID时不默认视为通过，需重新构建或消费已有明确验收的逐镜像收据。status/stop兼容旧部署，不能因新门禁停止既有应用。

正式构建仍从固定提交快照；验证环境可以消费已验收固定制品，必须逐项保留各自真实源码/模式，不能声称旧制品是最新源码。没有应用源码变更时不机械重做既有构建。当前本地开发Docker保持原制品，隔离验证不覆盖`.local/docker-runtime/current.json`或派生runtime。

## 隔离环境

- 稳定`release-validation-v1`记录/恢复入口位于本项目私密`.local/release-validation/<id>/`。新ID先检查资源不存在再保存所有权记录；相同ID只允许恢复自己的资源，失败保留阶段/日志/进程，不能猜测结果后重复初始化。
- 每次新建独立三MySQL库及各自app/migrator、PG库/角色、S3桶/用户/策略、ES索引/用户/角色、Qdrant集合；不覆盖既有命名空间。应用只有DML，迁移身份不用于业务请求。Qdrant沿本项目专用实例API key管理集合，配置锁定独立集合和业务租户；不宣称已具备集合级独立凭据隔离。
- 检索命名空间允许显式项目配置：Qdrant使用`agentic_`加小写字母/数字及单下划线分段，ES对应`agentic-`及单连字符分段，长度均不超过96；两者规范化后必须相等。原开发/test名字保持兼容，禁止通配符、逗号、多索引、路径、空段和不匹配配置。命名规则只限制配置，不替代资源凭据授权。
- 独立Compose project和明确loopback端口，复用原Compose结构的派生配置；源制品ID固定。原服务不停止、不变更，私密配置和密钥外置0600，日志不打印连接串或凭据。
- 验证仅合成数据/资金，不能复制真实累计账本为新额度。模型提供方密钥不进入隔离配置，出口指向本机受控验证端点或被禁用；模型生成质量不属于本片验收。原账本摘要前后核对。
- Web本地模式允许配置显式`http://127.0.0.1:<port>`外部origin，容器监听端口独立保留；Host/Origin精确匹配、显式请求头、fetch-site和路由白名单维持，非loopback、路径/query/凭据拒绝。默认仍28086；正式OIDC模式不启用本地身份桥。
